# P0.7 — Local Wine runtime import

Boreal can use an existing Wine application without continuing to depend on a mutable installation in `/Applications`.

## Discovery

- Boreal checks `/Applications` and the current user's `Applications` folder for app bundles with the canonical WineHQ layout: `Contents/Resources/wine/bin/{wine,wineserver,wineboot}`.
- It reads the product name, Wine version, and minimum macOS version from the bundle metadata.
- Thin and universal Mach-O headers are inspected directly. On Apple silicon, an x86_64-only Wine build is marked as requiring Rosetta 2.
- Discovery is read-only. Boreal does not modify or launch the source app until the user explicitly chooses **Import**.

## Transaction and trust boundary

An import copies the complete app bundle into a unique staging directory under `Application Support/Boreal/Runtimes/.installing`. Boreal then:

1. creates its canonical runtime directory structure;
2. rejects symbolic links that resolve outside the snapshot;
3. writes a versioned runtime manifest, SPDX document, and source/trust notice;
4. checks the required executables and reported `wine --version`;
5. performs an isolated `wineboot --init` smoke test;
6. atomically moves the completed runtime into place; and
7. makes the snapshot read-only.

Any failure removes staging and partially published output. The original app remains unchanged.

A local snapshot is shown as **Validated**, not **Verified**. Validation proves that the copied structure and smoke test work locally; it does not claim that Boreal signed, notarized, or supplied the original Wine app. Catalog runtimes retain the stronger signed-manifest and SHA-256 verification path.

## Current-machine boundary

The development Mac currently contains Wine Staging 11.15 in the supported canonical layout. Boreal can offer it in Components, but the real 711 MB copy is intentionally started only by an explicit user click. Automated tests use a small synthetic Wine app and verify discovery, atomic import, validation, immutability, and cleanup without modifying `/Applications` or the user's real Boreal data.
