# P1.2 — Epic Games via Legendary

Boreal integrates Epic Games through the open-source Legendary CLI while owning the native SwiftUI account, library, artwork, and operation UI.

## Trust and authentication

- Epic support is installed only after an explicit user action.
- Boreal downloads the architecture-specific Legendary 0.21.0 release directly from the upstream GitHub release.
- The arm64 and x86_64 binaries are pinned to the SHA-256 digests published in the GitHub release metadata. A mismatch aborts installation before the file becomes executable.
- Legendary runs with `LEGENDARY_CONFIG_PATH` pointing to `Application Support/Boreal/Accounts/Epic`, so it does not share or overwrite another Legendary installation.
- Boreal opens Legendary’s Epic web-login page. The user signs in with Epic and pastes the returned one-time `authorizationCode`; Boreal never asks for an Epic password, CAPTCHA, MFA value, or browser cookie.
- Disconnect invokes Legendary’s credential deletion and removes Epic entries from Boreal’s persisted library without deleting downloaded game files.

Legendary is a separate GPL-3.0 project. Boreal links to its source and license in the Accounts screen and downloads the unmodified executable on demand rather than embedding its source into the application target.

## Library and installation

`legendary list --platform Windows --json` supplies the owned Windows library and Epic metadata. Boreal maps stable Legendary app names, titles, descriptions, developers, and key images into its persisted store-game model. `legendary list-installed --json --show-dirs` supplies installed state and paths.

An explicit confirmation starts `legendary -y install <app> --platform Windows --base-path <Boreal Games/Epic> --skip-dlcs`. Boreal displays the operation state and refreshes the Epic library after completion. The operation runs as one managed task and reports helper-provided progress in Downloads, including percentage, transferred/remaining bytes, rate, and ETA when Legendary provides enough information.

After installation, **Prepare to Play** creates a dedicated Boreal environment and asks Legendary for `launch <app> --json` parameters bound to the selected Wine executable and prefix. Boreal validates that the executable and working directory remain inside Legendary's installed-game directory. Each launch refreshes this plan so expiring Epic parameters are never persisted as a permanent command.

Legendary-supplied environment variables are passed through, except `WINEPREFIX` and `PATH`: Boreal always replaces those two with its managed environment and immutable runtime. The launch then uses the regular Boreal process/session monitor, including stop, force quit, and restart recovery. Non-empty Legendary pre-launch shell commands are rejected rather than executed implicitly.

## Verified boundary

- The application build passes after the integration.
- The signed test suite executes real local helper processes and verifies account detection, JSON mapping, artwork, installed state, the Windows install command contract, launch-plan validation, and isolation of `WINEPREFIX`/`PATH`.
- A live download smoke test accepted the upstream arm64 artifact only after matching SHA-256 `28f5f7d0eb8c029679d4faaa483ec85888af17a9a75977ae9170c21d8ce3428b` and confirmed that the installed file is executable.
- No real Epic account was connected and no owned game was downloaded during automated verification. Those actions require the user’s Epic authorization and game choice.
- No real owned Epic title was launched during automated verification. The end-to-end code path is implemented, but a live game result still depends on the user's authorization, selected title, anti-cheat requirements, and Wine compatibility.
