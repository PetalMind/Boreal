# P1.3 — GOG Library

Boreal integrates GOG through the open-source `heroic-gogdl` helper used by Heroic Games Launcher.

## Component trust

- Version: `heroic-gogdl 1.3.0`
- Source and license: <https://github.com/Heroic-Games-Launcher/heroic-gogdl> (GPL-3.0)
- macOS arm64 SHA-256: `a85ae9ef80a3e7840b19a416dd4b3c5db2054508c6147315f1c22faa63a29b38`
- macOS x86_64 SHA-256: `a3d1e20f09371eb9032a4837eb576b585456728a6f2f420e6877e5cccd4c434d`

The helper is downloaded only after an explicit user action, verified before installation, and stored under Boreal's Application Support directory. A failed digest never replaces an installed component.

## Authentication and data

GOG sign-in happens on GOG's own authorization page. Boreal receives only the one-time authorization code and passes it to `gogdl auth --code`. Passwords, CAPTCHA, cookies, and MFA never enter Boreal.

Tokens are stored in `Accounts/GOG/auth.json`. The library is fetched from the authenticated, paginated Galaxy Library endpoint. Per-title metadata comes from GOG GamesDB using the library certificate and includes available artwork, descriptions, supported operating systems, screenshots, and ratings.

Disconnecting removes local tokens and GOG rows from Boreal. Downloaded games remain on disk.

## Installation and launch

Windows builds are installed under `Games/GOG/<game-id>` with `gogdl download --platform windows`. Boreal accepts an installation only when `goggame-<id>.info` exists.

The primary file play task is parsed from that file. Executable and working-directory paths are resolved through symlinks and must remain inside the game directory. Boreal then launches the executable with its selected immutable Wine runtime and isolated prefix. URL tasks and escaping paths are rejected.
