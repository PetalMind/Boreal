# P1.5 — Operation progress and cancellation

## Product behavior

- Epic and GOG installs expose helper-reported percentage, byte counts, transfer rate, and ETA when available.
- Known manifest sizes are shown immediately, and Boreal derives downloaded and remaining bytes from the reported percentage when a helper omits byte counts.
- Steam for Windows owns the install/update progress UI. Boreal reports explicit client preparation and provider-waiting stages, then confirms completion from Steam's AppID manifest.
- Indeterminate phases still show a truthful stage message instead of a fabricated percentage.
- Active game work appears both on the game detail screen and in Downloads & Components.
- Cancel stops the tracked Swift task and terminates the attached `legendary` or `gogdl` process. A process that does not react to `SIGTERM` is force-terminated after two seconds.
- Cancelling a regular Windows installer also stops its Wine launcher and removes the incomplete managed environment.
- Cancelling environment preparation removes an environment created by that operation.
- Provider operation keys include both provider and external game ID so matching IDs from different stores cannot collide.

## Steam boundary

- Windows Steam owns depot download state, authentication, Steam Guard, patching, and verification. Boreal reports preparation and provider-waiting stages, then validates the installed AppID manifest before exposing the game as ready.

## Validation

- `StoreOperationSupportTests` covers percentage/byte parsing, fragmented helper output, provider progress lines, numeric remainder calculation, and termination of a real helper process.
- The full Boreal unit suite covers Epic, GOG, Steam for Windows, local/runtime installation, and environment recovery.
