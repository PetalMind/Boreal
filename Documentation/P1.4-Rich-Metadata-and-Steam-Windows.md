# P1.4 — Rich store metadata and Steam Windows builds

## Clear platform and compatibility labels

Boreal presents separate signals:

- **Native macOS** means the store declares a macOS build.
- **Windows via Boreal** means a Windows build can be prepared in Wine.
- **ProtonDB compatibility** is community evidence for the Windows build and is not a guarantee for Boreal on macOS.
- **Store rating** is the platform's user/critic score and is not a compatibility score.

This prevents a highly reviewed game from being mistaken for a game known to run well through Wine.

## Steam media and ratings

Steam enrichment reads the store's app details and review summary in parallel. When provided by Steam, Boreal persists and displays:

- portrait artwork, header, and background;
- screenshots and trailer thumbnails/video URLs;
- Windows and native macOS availability;
- positive-review percentage, review count, review label, and Metacritic score.

Existing local Steam cache artwork remains the preferred offline cover.

## Epic and GOG metadata truth

Epic library metadata is mapped using the image roles and platform declarations returned by Legendary: tall game/store art becomes the portrait, wide game-box art becomes the banner/background, and screenshot-typed assets are included only when Epic actually returns them. Boreal does not synthesize an Epic rating or trailer when the library metadata contains neither.

GOG GamesDB supplies portrait and wide art, backgrounds, screenshots, supported systems, descriptions, and aggregated critic ratings where available. Missing assets remain visibly absent instead of being copied into unrelated media roles.

A read-only live smoke check against the already connected local sessions confirmed that the production service imports both libraries without exposing account credentials. At the validation snapshot, Epic returned complete portrait/banner/platform metadata for all imported entries, while GOG returned partial coverage appropriate to its per-game catalog records. Exact counts are account- and catalog-dependent and are therefore not product constants.

## Windows-only Steam games

For a Steam game that declares Windows support but no native macOS build, the detail page offers **Install Windows Version**.

The workflow downloads Valve's official mutable bootstrapper from the installer link published on Steam's About page, requires HTTPS on Valve's exact CDN host, checks for a successful response, a plausible minimum size, and a Windows `MZ` header, then installs it in a Boreal-managed environment. Unlike immutable helper releases, this bootstrapper intentionally updates over time and therefore is not pinned to a permanent digest.

Account credentials and Steam Guard are entered only into the Windows Steam client running inside the isolated prefix. Boreal sends `steam://install/<AppID>` to install and `steam.exe -applaunch <AppID>` to launch. The first Windows Steam environment is reused for later Steam games so its authorized session and game files are not duplicated.

The workflow does not claim a game download is complete merely because the Steam client accepted the install command. Steam remains the source of truth for download progress, updates, DRM, and launch readiness.
